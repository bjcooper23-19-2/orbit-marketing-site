# Build brief and implementation record

Risk class: **Standard**. The goal is a credible public home that lets Ben explain Orbit with one link. The implementation is a static multipage site with shared navigation/footer, eight routes, approved assets and SEO foundations. Registration links now lead to the owner-provided Tally form and contact links use the confirmed public address. There is no account system, CMS or backend in this site.

The site is generated by `scripts/build.mjs` from `src/site.mjs`, `src/legal.mjs` and `src/styles.css`. Relative asset and route links support GitHub Pages under `/orbit-marketing-site/` as well as the intended domain. Metadata uses the confirmed `myfamilyorbit.uk` canonical origin. The production-config build allows indexing of public pages; the Pages workflow deploys automatically after a successful build and check on pushes to `main`. Its manual trigger is reserved for owner-approved recovery or redeployment. The current apex redirects to the app; the [readiness handover](publication-readiness.md) records the cutover sequence.

Product reference: `bjcooper23-19-2/my-family-orbit@546c34e5ae3e3ffe7c95482b612333cda0a87b3e`. Source files inspected include README, AGENTS, product brief, product loop, validation roadmap, terminology/state model, information architecture, implemented CSS, Tailwind config, logo component, favicon and brand memory. Existing tracked synthetic demo screenshots supplied the product imagery. No product files were modified.

Validation: `npm run build`, `npm run check`, route/overflow and mobile-menu inspection at 375, 390, 768, 1024 and 1440 px, and desktop/mobile screenshots of all core pages. Evidence is kept locally in ignored `artifacts/` and summarised in the PR. Publication blockers are tracked in `docs/publication-checklist.md`.
