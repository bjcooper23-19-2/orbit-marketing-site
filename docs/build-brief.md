# Build brief and implementation record

Risk class: **Standard**. The goal is a credible public home that lets Ben explain Orbit with one link. The smallest complete implementation is a static multipage site with shared navigation/footer, eight routes, approved assets, SEO foundations and inactive integrations. There is no commercial launch funnel, account system, CMS or backend.

The site is generated by `scripts/build.mjs` from `src/site.mjs` and `src/styles.css`. Relative asset and route links support GitHub Pages under `/orbit-marketing-site/` as well as the future domain. Metadata uses the proposed `myfamilyorbit.uk` canonical origin. The review build is `noindex` and disallows crawling. `site.config.json` holds future destinations. The manual-only Pages workflow must not be run until publication is approved.

Product reference: `bjcooper23-19-2/my-family-orbit@546c34e5ae3e3ffe7c95482b612333cda0a87b3e`. Source files inspected include README, AGENTS, product brief, product loop, validation roadmap, terminology/state model, information architecture, implemented CSS, Tailwind config, logo component, favicon and brand memory. Existing tracked synthetic demo screenshots supplied the product imagery. No product files were modified.

Validation: `npm run build`, `npm run check`, route/overflow and mobile-menu inspection at 375, 390, 768, 1024 and 1440 px, and desktop/mobile screenshots of all core pages. Evidence is kept locally in ignored `artifacts/` and summarised in the PR. Publication blockers are tracked in `docs/publication-checklist.md`.
